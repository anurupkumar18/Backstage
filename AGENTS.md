# Backstage coding agents

Follow the repository's [contribution and ownership rules](CONTRIBUTING.md). Read the [original team handoff](BACKSTAGE-team-agent-handoff.md) and your lane's kickoff guide before editing.

## Read before working

- At the start of a task, when resuming, and after fetching new commits, follow the [team update read checklist](docs/handoffs/README.md). Read the latest pushed entries for each active lane and inspect the diffs that affect your task. Include the reviewed branches and commit IDs, plus any dependency that changes your work, in your first update after the review.
- If your checkout predates these instructions, use the copy on `origin/main`. Flag missing access or an unclear handoff before proceeding with work that depends on it. Record what you could verify.

## Write before pushing

- Every push must include a new entry in the log for the lane that owns the branch. Use the [entry template](docs/handoffs/README.md#entry-template). Cover everything being published, including changes another lane must pick up, and put the note in the same push as the work.
- Preserve earlier entries. Append corrections and link to the entry they supersede. Keep reproduction steps and decisions in the repo, and link to commits, tests, contracts, or runbooks as evidence.
